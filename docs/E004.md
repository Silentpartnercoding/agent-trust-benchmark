# E004 exploratory protocol: cross-runtime delegated authority continuity

## Status

**Exploratory implementation test.** This protocol evaluates a portable
benchmark extension. It is not a production deployment or a claim about an
unexercised provider.

## Frozen question

Can a human-authorized Agent A give a strictly smaller, short-lived authority
to an SDK-free Agent B, with an independent resource gateway verifying the
complete Human -> A -> B chain before effect and producing verifiable lineage?

## Existing primitives reused

- E002 Human Authorization Receipt and caller-owned verification context;
- detached/compact Ed25519 JWS helpers and proof-of-possession key binding;
- fail-closed verification with trusted external keys, signed capability
  ceilings, audience, expiry, revocation status, and zero downstream calls
  after deny;
- neutral principal, subject, delegation, and action binding;
- append-only, content-addressed receipt practices.

The experiment does **not** claim that the current Knowledge Ledger already
verifies delegated authority. Its current transaction evaluator addresses
search coverage and evidence roots. E004 adds a deliberately isolated
authority-lineage receipt so the missing composition can be measured.

## Fixed architecture

```text
Human H --signed HAR--> Agent A --attenuated JWS--> foreign Agent B
                                                    |
                                                    v
                                    local enforcement gateway
                                      | verify complete chain
                                      | check action/audience/time/revocation
                                      | verify B possession proof
                                      | consume request id
                                      v
                                      mock resource
                                      |
                                      v
                         signed, hash-chained authority receipts
```

Agent B is a standalone Python standard-library program. It imports no module
from this benchmark or any proprietary agent SDK.
It treats the delegation token as opaque and uses OpenSSL only to sign a small
request statement with its own test key.

## Fixed authorities

- Human H authorizes Agent A for `notion:read_page` and `notion:create_page`.
- A delegates only `notion:create_page` to B.
- Audience is `urn:atb:e004:notion-gateway`.
- The delegation is subject/key-bound to B, expires in ten minutes, and sets
  `can_redelegate=false` with zero remaining delegation depth.
- Only the gateway owns the mock resource credential.

## Required tests

1. Valid H -> A -> B `create_page`: allow and one resource effect.
2. B requests `read_page`, `archive_page`, or `admin_workspace`: deny and zero
   additional effects.
3. A attempts to delegate `admin_workspace`: reject.
4. Tampered delegation: reject.
5. Expired delegation: reject.
6. Revoked parent or child: reject.
7. Wrong audience: reject.
8. Agent C presents B's artifact with C's proof: reject.
9. B attempts B -> C while redelegation is disabled: reject.
10. Replayed request identifier: reject; a fresh request under the same valid
    delegation remains permitted until expiry or revocation.
11. Ledger mutation: receipt-chain verification fails.
12. Static dependency check: foreign Agent B contains no proprietary import.

## Success rule

The result is supported only if the valid create is executed exactly once,
every prohibited attempt executes zero times, the foreign-agent dependency
check passes, the full receipt chain verifies before intentional mutation, and
mutation is detected. Passing establishes the exercised cryptographic and
enforcement path only. It does not establish universal enforcement: a resource
endpoint or raw credential reachable outside the gateway remains a bypass.
