# E005 exploratory protocol: authorized invocation (Mandate)

## Status

**Exploratory implementation test.** This is the companion to E004's
derived-delegation proof. It is isolated benchmark code, not production Notion
behavior or a claim about an unexercised provider.

## Frozen question

Can Agent A, which is authorized to request one exact Notion archival, instruct
an SDK-free Agent B to perform it using authority B independently received
from a Notion administrator—without falsely claiming that A delegated B's Notion
permission?

## Fixed distinction

```text
DELEGATE
Human H -> Agent A -> Agent B -> resource
                    derived authority; child <= parent

MANDATE / authorized invocation
Human H -> Agent A --signed exact request--> Agent B -> resource
Notion admin ----------------independent grant--^
```

E005 exercises only the second shape. Both paths are required:

1. A must have caller-approved authority to **request/cause** `archive_page`;
2. B must independently have authority to **execute** `archive_page`;
3. A's signed mandate must bind B's key, the gateway audience, resource,
   action, target, payload, time window, request-authority receipt, and
   revocation handle;
4. B must prove possession of its bound key and bind its request to both the
   mandate and its independently issued execution credential;
5. only the gateway holds the downstream mock-resource credential.

The mandate transfers no permission. Therefore the delegation subset rule is
deliberately absent. Its replacement is a two-path conjunction:

```text
A may request exact action
AND
B may execute exact action
AND
signed mandate and request match
= ALLOW
```

## Fixed scenario

- Workflow authority grants A `notion:request_archive_page`.
- Notion administrator independently grants B `notion:archive_page`.
- A mandates archival of exactly `notion:page:123` with one fixed payload.
- The mandate lasts ten minutes.
- Agent B is a standalone Python standard-library program. It parses neither
  security artifact and imports no proprietary SDK.

## Required adversarial matrix

1. Both paths valid: ALLOW and one effect.
2. B can archive but A cannot request archival: DENY.
3. A can request archival but B cannot execute it: DENY.
4. Tampered, ambiguous-type, or expired mandate: DENY.
5. Wrong audience, target, or payload: DENY.
6. Wrong Agent B or wrong executor-authority subject: DENY.
7. Replayed request: DENY.
8. Revoked mandate, A request authority, or B executor authority: DENY.
9. Receipt binds both authority paths and one exact effect.
10. Ledger mutation: verification fails.
11. Static dependency check: foreign B imports no proprietary SDK.

## Success rule

Supported only if the one valid request causes exactly one effect, every
adversarial request causes zero additional effects, the SDK-free check passes,
and the signed hash-chain detects mutation. Passing establishes this isolated
dual-authority thin slice only. It does not establish a production Notion
integration, external interoperability, standardization, or universal
non-bypassability.
