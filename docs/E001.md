# E001 preregistration: Human -> Agent -> Action

## Frozen question

Can an independent observer establish who authorized an AI agent, the exact
authority it received, whether that authority was enforced, what the agent did,
and whether revocation stopped it?

## Sequence

1. Create a human principal and a distinct agent identity.
2. Create a human-to-agent delegation limited to `payments:preview`.
3. Issue and inspect the credential or signed authority object.
4. Attempt `payments:preview`; it must succeed exactly once.
5. Attempt `payments:execute`; it must be blocked before effect.
6. Reconstruct attribution from provider or enforcement evidence.
7. Revoke the grant.
8. Retry `payments:preview`; it must be blocked.
9. Measure elapsed time from acknowledged revocation to the first proven block.

## Binary outputs

- `DISTINCT_AGENT_IDENTITY`
- `DELEGATION_PROVABLE`
- `SCOPE_VISIBLE`
- `ALLOWED_ACTION_SUCCEEDS`
- `FORBIDDEN_ACTION_BLOCKED`
- `HUMAN_ATTRIBUTION_PROVABLE`
- `AGENT_ATTRIBUTION_PROVABLE`
- `ACTION_AUDITABLE`
- `REVOCATION_SUPPORTED`
- `POST_REVOCATION_ACTION_BLOCKED`

## Numeric outputs

- `REVOCATION_LATENCY_MS`
- `TOKEN_LIFETIME_SECONDS`
- `EVIDENCE_COMPLETENESS_PERCENT`

## Status vocabulary

- `PASS`: directly supported by evidence produced in this run.
- `FAIL`: the run directly contradicted the requirement.
- `BLOCKED_EXTERNAL_ACCESS`: the provider could not be exercised because
  external access or configuration was unavailable.
- `NOT_SUPPORTED`: the exercised provider surface explicitly lacks the feature.
- `INDETERMINATE`: the available evidence cannot decide the requirement.

Absence is never inferred from an unsearched surface. A provider adapter may
say `NOT_SUPPORTED` only when the exercised interface makes that boundary
explicit; otherwise it says `INDETERMINATE`.

## Fairness rules

- Every provider receives the same semantic task and output schema.
- Provider-native terminology is preserved in raw references but normalized
  only at the evidence boundary.
- Benchmark-generated observations are labelled as such; they are not called
  provider-native receipts.
- Credentials, tokens, private keys, and full signed objects are never stored.
- A local reference implementation is mandatory so the harness itself can be
  falsified before vendors are compared.
- Results compare exercised surfaces, not whole companies or unseen products.
